# Server-authorized moderation actions

moderateCommunityReport accepts reportId, action (reopen/dismiss/hide/restore) and expectedStatus. It verifies the revoked-token-aware bearer, UID/auth_time/no-tenant constraint, and an explicit server-owned moderator roster copied from the existing client roster to preserve current permissions. It never accepts roles from user-writable profile fields or request payloads. Roster changes currently require server code deployment. Client roster remains only a UI visibility hint.

The transaction checks session cutoff, moderator account availability, report existence/type and expected current status. It resolves target IDs from the stored report, checks post existence and unambiguous nested comment existence, and commits content changes together with report status and server-stamped reviewer/history. It uses update on existing posts and nested moderation fields, preserving other moderation metadata and never recreating deleted posts. Account hiding remains unsupported; account restore retains the prior report-status-only behavior. Post restore retains cleared status and resets report counters. Dismiss/reopen do not alter content state.

Client replaces all four direct moderation writes with one callable helper and suppresses overlapping local actions. Expected status detects status changes, not every concurrent edit or changes made through another report for the same content; there is no exactly-once receipt. Firebase Auth checks occur before the transaction. Existing history remains in the report document (growth limit still applies).

Deploy callable before client. Direct moderation writes must later be denied in reconciled Firestore rules; old clients can otherwise bypass this callable. Inbox counts/list streams and moderator content preview reads remain direct and require the next migration. No live roles or services changed, no deployment, no runtime tests. Deferred: nonmoderator/forged-role/revoked/disabled access, all actions, conflicting status, deleted targets, nested comments, retries, metadata preservation and UI.
